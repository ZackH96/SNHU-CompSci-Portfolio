The client for this project was DriverPass, specifically the owner, Liam. They were seeking to provide better training resources for prospective drivers. The system type they wanted built was a learning management system for driver education with scheduling capabilites for on-road practice with a driver instructor and a vehicle. The system allows users to create accounts, access study materials, take online practice exams, schedule in-person on-road driving practice sessions, and track their progress. Administrative functions include user account management, content updating, and integration with DMV guidelines. The goal was to provide a user-friendly platform that combined online training with practical on-road lessons to increase passing rates for new drivers.

I interpreted user needs by reading them and doing my utmost to fit them somewhere in the design where they made sense. I'm not sure exactly what else "interpet" could mean beyond read and implement in this specific context. It is extremely important to consider user needs when designing because of the simple fact that the user is who would be using the system being designed, whether that's the client or the end user. Without considering user needs, the system would fail, because a system is designed around the user by default.
I approach designing software, despite my limited experience, by finding out what the system is supposed to do, not do, who wants it made, how they want it made, and how the end user fits into how the client wants it built. My biggest technique for that is a simple one, reading a proposal from a client, and listening during an in-person or online disucssion to what the client wants that system to do. Lining up those spoken requirements with a proposal or requirements document is key to my strategy.
